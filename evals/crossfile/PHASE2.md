# Exploratory repair, declared before execution

The frozen pilot had 12 attempts: only five completed. Its vulnerable-version
agent completion assumed the semantics of pcap_open_live without reading it.
This phase is development on a known case, not held-out validation.

Run exactly one attempt per arm per snapshot (four attempts), retaining all
failures. No SDK retries or replacement attempts. Same model, source snapshots,
focal input, target, and scoring rubric as PROTOCOL.md. Both arms receive a
compact output instruction to avoid excessively long quotations. The agent
also receives a generic implementation-inspection procedure, twelve model calls
instead of eight, and a 240-second run deadline instead of 120. Single remains
one call. These changes are a package; improvement cannot be attributed to one
individual change. The same combined $1 ledger cap applies, including the pilot
and earlier evaluations. Unknown usage retains the original conservative reserve.

Order: vulnerable single, vulnerable agent, fixed agent, fixed single.
Score raw labels separately from verified mechanism and inspected evidence.
A favorable result is an illustrative case only, not an accuracy estimate or
proof against a single call supplied equivalent retrieved context. This is a
function-review adaptation of the published case, not a PR-diff evaluation.
